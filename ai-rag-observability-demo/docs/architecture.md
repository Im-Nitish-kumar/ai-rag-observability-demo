# Architecture — AI RAG Observability Demo

This repo is a runnable demo for tracing LangChain and LlamaIndex applications with OpenObserve.

## Observability stack

The demo is built on a four-layer observability pipeline:

1. Application: the LangChain or LlamaIndex backend that handles user chat requests.
2. OpenLLMetry instrumentation: framework-specific auto-instrumentation packages that create OpenTelemetry spans for each component.
3. OpenTelemetry SDK: the Python SDK that creates a `TracerProvider`, attaches a `BatchSpanProcessor`, and exports spans over OTLP HTTP.
4. OpenObserve: receives OTLP traces and stores them in a backend that understands OpenTelemetry and generative AI span conventions.

## LangChain instrumentation

LangChain is built on the Runnable protocol. Every component in a chain implements a common interface such as `invoke`, `stream`, `batch`, and async variants.

In this demo, the LangChain backend constructs a RAG chain using a retriever, a prompt template, a ChatOpenAI model, and a string output parser. When the chain runs, LangChain emits callback-like events for each stage of execution.

The OpenLLMetry package `opentelemetry-instrumentation-langchain` hooks into those events and creates spans for:

- runnable sequences and parallel structures
- retriever operations
- prompt formatting and prompt template execution
- OpenAI LLM calls through the LangChain wrapper

Each span includes timing information and attributes from the LangChain runtime. The OpenAI spans inside the chain also expose `gen_ai.*` attributes when the OpenAI instrumentation package is enabled.

## LlamaIndex instrumentation

LlamaIndex depends on a dispatcher-based execution model. The dispatcher layer emits signals for query execution, retrieval, response synthesis, and LLM calls.

The `opentelemetry-instrumentation-llamaindex` package attaches to that dispatcher hierarchy and creates spans for key operations such as:

- query engine entry points
- retrieval and vector store search
- response synthesizer execution
- LLM calls made by the index

Because the instrumentation uses OpenTelemetry standard spans, the output is consistent with the LangChain trace model even though the frameworks are different.

## OpenLLMetry and OpenTelemetry

OpenLLMetry is the instrumentation layer in this stack. It is not the backend, nor is it the SDK exporter. Its job is to observe framework execution and emit spans through OpenTelemetry.

The OpenTelemetry SDK is configured manually in `telemetry.py` for each backend. The SDK is responsible for:

- defining the service resource attributes
- batching spans for efficient export
- exporting spans to the backend OTLP endpoint
- optionally exporting spans to the console when `DEBUG=true`

The demo uses the OTLP HTTP exporter and sends traces to the OpenObserve ingest endpoint.

## `gen_ai.*` span attributes

OpenTelemetry defines a semantic convention for generative AI traces under the `gen_ai.*` namespace.

Typical attributes include:

- `gen_ai.system` — the AI provider or model system, such as `openai`
- `gen_ai.request.model` — the model name
- `gen_ai.request.temperature` — the temperature value used for the request
- `gen_ai.usage.prompt_tokens` — tokens used for the prompt
- `gen_ai.usage.completion_tokens` — tokens used for the completion
- `gen_ai.usage.total_tokens` — total tokens used
- `gen_ai.prompt.0.content` — the prompt text
- `gen_ai.completion.0.content` — the completed text

In this demo, OpenAI spans generated by the LangChain and LlamaIndex OpenAI instrumentors carry these attributes. OpenObserve can index them as structured fields.

## Span hierarchy for a LangChain query

A typical LangChain trace in this demo looks like:

- `chat.request` (root span created by the `/chat` endpoint)
  - `RunnableSequence` or `RunnableParallel`
    - `Retriever` span for the vector search
      - `Embedding` span or related retrieval spans
    - `ChatPromptTemplate` span for prompt formatting
    - `ChatOpenAI` span for the model call
      - `gen_ai.*` attributes for prompt, tokens, and completion

The OpenAI span is usually nested inside the LangChain runnable span, so the trace shows the full end-to-end latency and the relative cost of each stage.

## Span hierarchy for a LlamaIndex query

A typical LlamaIndex trace looks like:

- `chat.request` (root span created by the `/chat` endpoint)
  - `QueryEngine.query` span
    - `Retriever.retrieve` span
      - `VectorStore.query` span
    - `ResponseSynthesizer` span
      - `LLM.chat` span
        - `gen_ai.*` attributes from the OpenAI call

The structure is similar to the LangChain trace, but the root of the application-level work is the query engine instead of the runnable chain.

## Feedback trace linking

The demo cannot update finished spans after the fact, so the feedback route emits a separate feedback span.

The feedback span includes:

- `feedback.rating`
- `feedback.comment`
- `linked_trace_id`

When OpenObserve displays the trace, the feedback span can be correlated with the original query by the trace ID.
